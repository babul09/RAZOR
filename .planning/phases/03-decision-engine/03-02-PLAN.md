## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Policy YAML -> PolicyEngine | Untrusted config values become guardrail limits; invalid YAML must fail loudly. |
| PolicyEngine -> decision_engine | Block/approval outcomes gate every action; must be a hard gate. |
| ActionExecutor -> OutcomeVerifier -> PostgreSQL | Simulated outcomes write recovery_outcomes; no real payment side effects. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-03-05 | Tampering | policy config | medium | mitigate | Validate/coerce YAML fields with defaults; reject malformed policy files with ValueError. |
| T-03-06 | Tampering | policy hard gate | high | mitigate | PolicyEngine.check always runs before any action; BLOCK/APPROVAL_REQUIRED short-circuits execution and is audited. |
| T-03-07 | Tampering | discount bound | medium | mitigate | DISCOUNT_OFFER discount_rate capped at max_discount_percent inside the engine. |
| T-03-08 | Tampering | outcome persistence | medium | mitigate | Single transaction for RecoveryOutcome + case status update; simulator-backed only (no real APIs). |
| T-03-SC | Tampering | dependency/runtime | high | mitigate | Use only declared deps (sqlalchemy, pyyaml if added -> declare first); no real payment integration. |
</threat_model>
